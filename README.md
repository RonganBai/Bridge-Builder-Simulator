# Bridge Architect 3D（初版）

Godot 4.x .NET + C# 开发的 3D 建桥物理模拟游戏。玩家用有限资金在两岸锚点之间用木梁、钢梁、钢索和道路桥面建桥，然后启动通车测试，看轿车和重型货车能不能安全过桥。

> **验证状态（务必先读）**
> 已在 .NET SDK 8.0.428 下验证：`dotnet build BridgeArchitect3D.csproj` 编译通过（0 错误）；`dotnet run --project Tests/BridgeTests` 验收测试 A~H 与三关参考方案**全部通过**。
> 尚未验证：在 Godot 编辑器中实际打开、运行场景和界面交互。

## 2. 本地验证步骤

```bash
cd BridgeArchitect3D
```

1. **运行无界面验收测试（A~H + 三关参考方案）**，不需要 Godot：

```bash
dotnet run --project Tests/BridgeTests
```

   每项输出 `[通过]` 或 `[失败]`，全部通过时返回码为 0。

2. **编译游戏程序集**：

```bash
dotnet build BridgeArchitect3D.csproj
```

3. 用 Godot .NET 编辑器“导入”`project.godot`，点击右上角 **Build**（锤子图标），然后按 **F5** 运行。
4. 手动走一遍流程：主菜单 → 开始游戏 → 顶栏“参考方案” → 开始测试 → 过关 → 下一关。

## 4. 项目结构

```
BridgeArchitect3D/
├── project.godot / BridgeArchitect3D.csproj
├── Scenes/            MainMenu.tscn、LevelScene.tscn（其余对象由代码程序化生成）
├── Scripts/
│   ├── Data/          纯 C# 数据模型：材料、车辆、关卡、BridgeDesign、SimulationResult、GameDatabase（JSON）
│   ├── Building/      DesignEditor（建造规则 / 预算 / 撤销重做，纯 C#）、BuildingManager（输入交互）、
│   │                  BridgeRenderer（节点 / 构件 / 桥面显示）、MaterialManager、IBridgeMechanism（预留）
│   ├── Physics/       IStructuralSolver、StructureSolver（二维桁架刚度法）、StructuralModel、
│   │                  LoadCalculator、FailureDetector、BridgeSimulation（通车测试逻辑，纯 C#）
│   ├── Traffic/       RoadPath（桥面路径）、TrafficEventSystem（预留火车 / 船舶事件）、
│   │                  TrafficManager（测试驱动 / 回放 / 碎片）、VehicleController（程序化车辆）
│   ├── Camera/        OrbitCamera
│   ├── World/         TerrainBuilder（地形、水面、天空、灯光）
│   ├── UI/            GameHUD、MainMenu、UiTheme
│   └── Core/          GameManager（Autoload）、LevelManager、SaveManager
├── Data/              materials.json、vehicles.json、levels.json、ReferenceDesigns/*.json
└── Tests/BridgeTests  无界面验收测试工程（直接编译上面的纯 C# 源码）
```

和需求里的目录示例相比有这些调整：

- 节点、构件、桥面、车辆不做成单独的 `.tscn`，而是由 `BridgeRenderer` / `VehicleController` 用代码生成。这样场景里不会出现缺失的资源引用。
- 桥面和梁共用 `BridgeMember`，通过材料的 `ComponentType = Deck` 区分。需求里 BridgeDeck 的 `Width` / `LoadLimit` 对应材料的 `DeckWidth` / `BendingCapacity`。
- 物理、建造规则、通车逻辑都**不依赖 Godot**，可以直接单元测试。以后换成三维求解器时，只需要实现 `IStructuralSolver`。

## 5. 结构模拟原理

- **模型**：二维刚架 / 桁架混合模型。所有节点位于 Z=0 的竖直平面，但数据里保存的是三维坐标。显示时桁架在桥面两侧各画一片。
  - 木梁、钢梁、道路桥面、混凝土柱是**刚接梁单元**（EA + EI），节点能传递弯矩。缺少斜撑的桥面会像悬臂梁或连续梁一样受弯，而不是一缺支撑就直接碎掉，只是承载力会大打折扣。
  - 钢索、液压杆是**两端铰接的二力杆**，只受轴力。
- **刚度矩阵**：每个节点有 (ux, uy, θ) 三个自由度。只连接铰接杆的节点没有转角自由度。去掉支座约束自由度后组装刚度矩阵并求解，得到位移、轴力和端弯矩。
- **失稳检测**：消元时主元小于相对容差，就判定为机构（约束不足）；位移超过 3 m 视为发散。
- **钢索**：只能受拉，受压时标记为松弛并重新求解。
- **承载力**：
  - 受拉：ft·A。受压：min(fc·A, π²EI/L²)，长压杆会屈曲。
  - 刚接构件按“轴力 + 弯矩”叠加校核：N/Nu + M/Mu ≤ 1。M 是构件内的最大弯矩，等于端弯矩与简支弯矩（自重 + 车轴荷载）的叠加。
- **载荷**：构件自重平均分到两端节点；车轴荷载按车轴在桥面上的位置，线性分配到构件两端节点。
- **道路通行**：按几何判断。车轮下有桥面、高度差不超过 0.6 m，车就能前进；不超过 0.5 m 的缝隙可以直接驶过。桥面段交叠、不共用节点也能通行。
- **测试流程**：问题不会在 0 秒直接判负。不稳定的部分先垮塌，车辆照常出发：
  - 遇到断口：车被卡住，**3 秒后**判失败。
  - 驶上断裂的桥面：车坠落，测试立即失败。
  - 失败报告给出首个根本原因。
- **致命失效**：桥面断裂或随失稳垮塌、断裂构件数超过上限（连续失效）、锚点过载（锚点失效后结构继续垮塌）、桥面下沉超过限制。不影响桥面的局部构件掉落不算致命。
- **船只与液压杆**：第二、三关有船只按时间沿河道驶过桥位，航道净空在场景中用橙色框标出。
  - 船只进入桥位前 4 秒，所有液压杆自动收缩 25%；船完全离开后，液压杆在 4 秒内恢复原长。
  - 船只经过时，任何完好构件进入船体包络（航道宽 × 水面以上船高），都判定为撞船，测试失败。
  - 液压杆收缩在求解中按“强制伸缩”处理，会产生真实的位移和内力。画面上，液压杆伸缩按真实比例显示，只有弹性变形会被放大。
- **桥面断裂**：桥面断裂本身不会立即判负。车辆驶上断裂的桥面会坠落，导致失败；如果车辆没有经过断裂处，仍可通关，但会降低完整度分。
- **评分（上不封顶，通关后计算）**：预算 : 完整度 : 受力 的权重为 7 : 2 : 1。
  - 预算分 = 7000 × 提供预算 / 使用预算。用得越少分越高，超支时降低。
  - 完整度分 = 2000 × 通过后桥面完整度。
  - 受力分 = 1000 × max(最大受力利用率, 安全冗余)。安全冗余 = 承载力 / 峰值需求 − 1，上限 150%，超过不再加分。
  - 结算界面分别列出“通关 / 预算内 / 桥面完整”三项。
- **固定步长**（1/60 s），无随机数，相同条件下结果完全一致。
- **变形显示**：显示放大系数默认 30×，只影响画面；所有判定都用真实位移。

## 6. 关卡与参考方案

9 关按难度递增，每关只开放会用到的材料，并配有经过验证的参考方案。参考方案分三步查看：思路提示 → 左半座桥的局部示意 → 完整方案。下表是验收测试实测的结果：

| 关卡 | 新判断 | 交通 | 参考方案成本 / 预算 | 最大利用率 |
|---|---|---|---|---|
| 1 跨越小河 | 找断点、补支撑（起始桥只有木桥面） | 轿车 | $8,520 / $15,000 | 30% |
| 2 林间步道 | 木结构；胶合木梁限量 2 根 | 行人队伍 + 轿车 | $7,492 / $10,000 | 45% |
| 3 重型货车 | 同一座桥在两种荷载下的差别 | 轿车 + 货车 | $27,063 / $35,000 | 65% |
| 4 高低两岸 | 右岸高 2 m，桥面坡度 ≤ 15% | 轿车 + 货车 | $27,120 / $38,000 | 66% |
| 5 有限锚点 | 右岸单锚点 + 河中岩墩 | 2 轿车 + 货车 | $39,179 / $60,000 | 82% |
| 6 坦克通行 | 单点高负载（60 吨） | 货车 + 坦克 | $28,597 / $45,000 | 84% |

| 10 旧桥加固 | 改造锈蚀旧桥：修复、拆除（≤ 4 根）、加支撑 | 轿车 + 货车 | $6,308 / $9,000 | 89% |

| 12 洪水冲刷 | 木桥墩怕洪水，冲刷区浅基础会被掏空 | 轿车 + 洪水 + 货车 | $51,311 / $80,000 | 65% |

**桥墩与地基**：
- 桥墩工具（木桥墩 / 混凝土桥墩）：在河道里点击，桥墩从河床（或岩墩顶）立起，自动生成墩底基础、中部支点和顶部支点。点在桥面节点上时，墩顶直接顶住该节点。
- 顶部和中部支点可以上下拖动，也可以连接桥面和斜撑；墩底不能移动；删除墩底节点会拆掉整座桥墩。桥墩倾角不能超过 5°。
- 基础分浅基础（$1,500）和桩基础（$6,000），选中墩底节点后可以切换。地基承载力：岩石上的浅基础 3,000 kN，软土上的浅基础 400 kN，桩基础 4,000 kN。超过承载力，基础失效。
- 河床剖面按区域显示软土（褐色分层）和岩石（灰色），冲刷区用橙色虚线标出预设的冲刷轮廓。
- 洪水：水位上涨后，被淹没的木桥墩会被冲毁；水位达到峰值时，冲刷区里的浅基础被掏空、失去支撑；桩基础不受影响。
- 车队：新增空载厢式货车（3.5 t）和满载重卡（32 t），不同车型有不同的跟车距离。

**旧桥加固关的规则**：
- 旧桥原有构件不计费用，但承载力按“状况”折减（锈蚀钢梁 55%、旧桥面 80%）。旧构件显示为风化颜色。
- 旧桥节点不能移动。
- 选中旧构件可以“修复”：按损耗程度收费（新建价的 50% × 损耗比例），修复后承载力恢复到 100%。
- 拆除旧构件最多 4 根，拆除费 $60/m。
- 单靠一种手段不够：只修复（$3,808）或只加斜撑（$3,000），货车都过不了；修复加斜撑（$6,308）或加斜撑加钢上弦（$9,242）才能通过。

**车辆**：轿车 1.5 t；重型货车 25 t；公交车 15 t；坦克 60 t（两轴相距 1.2 m）；货运列车 160 t（4 节、16 轴、60 m）；行人队伍（15 人，共 1.2 t，步速 1.4 m/s）。同一层道路上车辆会保持跟车距离，起点被占用时后车会排队等待。

**新增材料**：
| 材料 | 特点 |
|---|---|
| 胶合木梁 | 最长 14 m，轻而强，表面显示层板纹理；部分关卡限量 |
| 钢筋混凝土梁 | 375 kg/m，很重；利用率超过 60% 先提示“开裂”，再继续加载才破坏 |
| 预应力 I 形梁 / 箱梁 | 最长 20 m / 28 m；预应力抵消部分弯矩，放置后上拱，加载后逐渐趋平 |
| FRP 复合桥面 | 95 kg/m，很轻，价格高、刚度低 |

**地形**：两岸可以不同高（场景中有坡度范围扇形提示）；禁止建墩区（场景中半透明绿色区域）；立交上层道路有高架引桥。

**规则（回归测试保证）**：两端有支撑时，每种桥面在自己的最大长度内都必须能承载规定车辆。木桥面要求承载轿车，其余桥面要求承载重型货车。
## 7. 已实现功能

- **主菜单**：开始游戏、选择关卡（含星级和解锁状态）、继续游戏、设置、退出。
- **3D 场景**：两岸、河床、半透明水面、河中岩墩、道路引道、锚点标记和标签、程序化天空、带阴影的平行光、可建造区域边界、建造网格。
- **相机**：右键旋转、中键平移、滚轮缩放（平滑插值）；重置、侧视（正交）、俯视（正交）、透视。
- **建造**：
  - 节点的创建、选择、拖动、删除；网格吸附和节点自动吸附。
  - 防止重复节点；禁止在河道水面以下建节点（两岸土体内允许，普通节点不提供支撑）；有建造区域约束。
  - 锚点不能移动、不能删除，普通节点永远不能变成支座。
  - 四种材料的连接预览；禁止零长度、重复、超长构件。
  - 预算实时同步，超预算时禁止建造并说明原因，删除构件会退还费用。
  - 撤销 / 重做（最多 200 步）。
- **受力显示**：
  - 建造模式下显示自重静力分析，测试模式下显示实时结果。
  - 颜色分级：绿 → 黄 → 红，失效 / 松弛显示为灰色。
  - 属性面板显示构件编号、材料、长度、质量、轴力、受拉 / 受压、利用率和安全状态。
- **通车测试**：
  - 测试前检查桥面连续性、坡度和跨度。
  - 车辆沿实际桥面路径行驶，车轴荷载真实作用到结构上。
  - 支持暂停、继续、重置、返回建造，以及 1× / 2× / 4× 速度。
  - 测试使用方案副本，不会改动原始方案。
- **断裂**：断裂的构件从求解里移除并重新分配载荷；同时生成刚体碎片（纯视觉效果）；车辆在桥面断裂时坠落。
- **失败分析**：
  - 弹窗显示失败原因、具体描述、发生时间、涉及构件、改进建议，以及“返回建造”和“重新测试”按钮。
  - 提供**首次失效快照**和最近约 6 秒的**回放**。
- **过关结算**：使用预算、剩余预算、最大利用率、通过车辆数、完成时间、星级（先满足通关条件，再按预算效率和安全程度评星）；“下一关”和“返回关卡选择”按钮。
- **存档**（JSON，保存在 `user://`）：
  - 关卡方案（节点、构件、材料、预算），加载时会重新校验费用和锚点。
  - 关卡进度、设置。
  - 开始测试和离开关卡时自动保存。
- **扩展预留**：`IStructuralSolver`、`TrafficEventSystem`（Train / Ship / Environment 事件类型）、`IBridgeMechanism`。

## 9. Windows 导出

1. Godot 菜单：编辑器 → 管理导出模板，下载与当前版本匹配的模板。
2. 项目 → 导出 → 添加 **Windows Desktop**。

## 10. 已知限制

- 尚未实现：钢—混凝土组合梁、弧形胶合木梁、温度伸缩、加固施工顺序（分段封闭）、双车道偏载、侧风与桥面扭转（需要横向 / 三维受力计算）。
- 地基与冲刷是简化模型：基础承载力按区域取固定值，冲刷按预设轮廓一次性生效，没有模拟河床的渐进侵蚀。
- 预应力只按“等效上托均布荷载”简化处理，没有计算偏心预应力的轴压效应；开裂只作为提示，不折减刚度。

- **代码没有编译和运行过**（见文首），可能存在少量编译错误或 Godot API 使用问题，需要在本地修复。
- 求解器是线性小变形桁架模型：
  - 不考虑节点抗弯、几何非线性、动力冲击和车辆加减速。
  - 屈曲用的是两端铰接欧拉公式。
- 建造只在单一竖直平面内进行。两侧桁架是同一片结构的镜像显示。
- 车辆之间没有碰撞和跟车逻辑，靠关卡里的时间间隔避免重叠。
- 碎片和车辆坠落只是视觉效果，不参与判定。
- 回放只保留失败前约 6 秒的历史，采样间隔 0.1 s。
- 中文字体使用系统字体（微软雅黑 / 黑体）。系统里没有这些字体时可能显示为方块。
- 没有音效。
